## 2. Wiring (the important part)

The SE100 uses the standard Pixhawk-style **6-pin** connector. Signal order:
`VCC, GPS-TX, GPS-RX, SCL, SDA, GND`.

There is **only one I2C pin pair** on the Jetson 40-pin header (pin 3 SDA / pin 5 SCL), and
the **OLED already uses it**. I2C is a shared bus, so the compass SDA/SCL are **spliced onto the
same two lines** as the OLED (each device keeps its own VCC + GND).

| SE100 wire | Signal | Jetson 40-pin header |
|---|---|---|
| VCC | 5V power | Pin 2 or 4 (5V) |
| GPS TX | GPS → Jetson | **Pin 10** (UART1 RX) — *crossed* |
| GPS RX | Jetson → GPS | **Pin 8** (UART1 TX) — *crossed* |
| SCL | compass clock | **Pin 5** (I2C, shared w/ OLED) |
| SDA | compass data | **Pin 3** (I2C, shared w/ OLED) |
| GND | ground | Pin 6/9/14/… (GND) |

**Gotchas baked in here:**
- **TX/RX must be crossed** (SE100 TX → Jetson RX, and vice-versa). Swapped = total silence.
- GPS baud is **38400**, *not* the u-blox default 9600.
- Compass is **IST8310** (WHO_AM_I @ reg `0x00` = `0x10`), **not** QMC5883 — it lives at `0x0e`.

## 3. The power-off incident (root cause + rule)

**Symptom:** while wiring the compass, the Jetson **fully powered off** (not a freeze/reboot).

**Cause:** a momentary **short across the 5V/GND rail** as the SCL/SDA wires were inserted next to
the adjacent 5V pins. The Jetson PMIC cut power to protect itself. `MAXN_SUPER` has the least
current headroom, so it trips most easily. **No damage** — board and I2C bus recovered fully.

**Rule learned:**
- A *full power-off* during wiring = **power-rail short**, not software.
- Always **power down** before touching the 40-pin header.
- After re-seating, an empty `i2cdetect` that's missing even the OLD device = something is
  unplugged or the bus is disturbed; once the OLED (`0x3c`) reappears the bus is healthy again.

## 4. Bring-up / verification commands

```bash
# --- GPS ---
# set baud + read raw NMEA for a few seconds:
stty -F /dev/ttyTHS1 38400 raw -echo
timeout 4 cat /dev/ttyTHS1
#   $GNRMC,...,A,...  -> "A" = valid fix ;  "V" = void (no fix yet, needs sky view)
#   $GNGGA,...,1,07,...  -> fix quality 1, 07 satellites

# --- Compass / I2C ---
i2cdetect -y -r 7          # expect 0x0e (compass) and 0x3c (OLED). No sudo: user is in 'i2c' group
i2cget -y 7 0x0e 0x00      # WHO_AM_I -> 0x10 confirms IST8310
```

If `i2cdetect` shows nothing: SDA/SCL not connected or swapped. If it shows `0x3c` but not
`0x0e`: only the compass's two data wires are loose.

## 5. Scripts in this folder

| File | What it does |
|---|---|
| `gps_read.py` | Continuous NMEA reader + decoded lat/lon/sats. `python3 gps_read.py [port] [baud]` (defaults ttyTHS1 @ 38400). |
| `compass_read.py` | IST8310 heading readout. Single-measurement mode, prints X/Y/Z µT + heading. `python3 compass_read.py [bus] [addr]` (defaults 7, 0x0e). |
| `gps_web.py` | **Browser dashboard** — GPS satellites/fix/position **+ live rotating compass dial**. `python3 gps_web.py [port] [baud] [http_port]` (defaults ttyTHS1, 38400, :8080). |
| `gps_monitor.py` | Terminal live monitor. |
| `gps_probe.py`, `gps_deepscan.py` | Baud/port discovery helpers (used during first bring-up). |
| `uart_loopback_test.py` | UART sanity check (loopback). |
| `compass_calibrate.py` | **Hard-iron + soft-iron calibration.** Spin the car flat through several 360 turns; writes `compass_cal.json`. Run in the final mounted position. `python3 compass_calibrate.py [bus] [addr]`. |
| `compass_cal.py` | Shared loader — `compass_read.py` and `gps_web.py` import it to subtract the saved offsets before computing heading. No file = identity (raw). |
| `compass_cal.json` | Saved calibration (offset + scale per axis). Generated by `compass_calibrate.py`. |

### IST8310 read sequence (reference)
1. Config once: reg `0x41` ← `0x24` (16× avg), reg `0x42` ← `0xC0` (pulse duration).
2. Trigger: reg `0x0A` (CNTL1) ← `0x01` (single measurement).
3. Wait for data-ready: poll reg `0x02` (STAT1) bit0, ~6 ms.
4. Read 6 bytes from reg `0x03`: X_L,X_H,Y_L,Y_H,Z_L,Z_H — little-endian **signed** 16-bit.
5. Scale ≈ **0.3 µT/LSB**. `heading = atan2(Y, X)` in degrees, normalize 0–360.

## 6. Web dashboard

```bash
cd "GPS"
python3 gps_web.py
# open http://localhost:8080  (Jetson) or http://<jetson-ip>:8080 (phone/PC on same Wi-Fi)
```

Now titled **"Jetson Dashboard"** — growing into the single place to watch everything.

Shows:
- **System (Orin Nano)** — live CPU%, GPU%, Memory% (colored bars), SoC temperature, and fan
  RPM/PWM. Read straight from `/proc` + sysfs via `sys_stats.py` (no jtop/psutil dependency, so it
  never conflicts with the OLED service's jtop client).
- **GPS** — link status, fix status, satellites in view / used in fix, signal SNR, position
  (+ map link), and the per-satellite SNR table.
- **Compass** — SVG needle rotating with heading (red = north end), X/Y/Z µT, and a `raw` /
  `calibrated` tag reflecting whether `compass_cal.json` is loaded.

GPS, compass, and system stats each run in their own daemon thread and publish into one shared
`STATE`; the compass reader shares the I2C bus with the OLED service without conflict. Any
unavailable source degrades to "—"/"not detected" and the rest keeps working.

## 7. Known limitations / next steps

- **Compass calibration:** `compass_calibrate.py` now does the 360° spin calibration (records
  per-axis min/max, subtracts center for hard-iron, scales for soft-iron) and writes
  `compass_cal.json`, which `compass_read.py` and `gps_web.py` load automatically. Run it **in the
  final mounted position**. ⚠️ **This is a STATIC calibration (motor off).** The SE100 sits on top
  of the 3D-printed VESC box — plastic gives **no** magnetic shielding, only the few-cm distance
  does. Once the motor is wired, its phase current adds a **throttle-dependent** field that static
  calibration can't remove: re-run an interference test (log X/Y/Z vs throttle), and if heading
  swings, move the compass to a standoff/mast away from the VESC/motor/battery wiring.
- **No tilt compensation** — heading assumes the board is roughly flat. Add accel-based tilt comp
  if the chassis pitches/rolls.
- **Motors will corrupt the compass.** IST8310 is very sensitive to magnetic fields/current.
  Mount the SE100 on a **mast/standoff away from the VESC, motor, and power wiring**, or headings
  will swing when driving. (#1 cause of bad rover compass readings.)
- **GPS fix needs sky view** — indoors shows 0 sats / status `V`. Outdoors → status `A` with
  lat/lon; cold start 30 s to a few minutes.
- **Integration:** bridge GPS fix + heading into the ROS 2 workspace (`~/sdc_ws`) as a nav source
  alongside camera perception.
